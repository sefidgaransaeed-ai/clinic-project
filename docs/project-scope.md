# محدوده پروژه

این فایل می‌گوید نسخه فعلی **چه چیزی هست و چه چیزی نیست**. اگر درخواستی بیرون از این محدوده بود، اول باید تیم درباره‌اش توافق کند.

## هدف

سامانه‌ای یکپارچه برای پشتیبانی از **امور اجرایی و مالی** یک مطب طب فیزیکی و توان‌بخشی، با رویکرد آموزشی و با کمک Claude Code.

تمرکز نسخه اولیه بر **امور اداری، نوبت‌دهی و مالی** است — نه نگهداری یا پردازش پرونده پزشکی و اطلاعات بالینی.

## داخل محدوده

| حوزه | قابلیت |
|---|---|
| نوبت‌دهی | درخواست نوبت از سایت، تأیید منشی، تقویم، وضعیت‌های نوبت، جلوگیری از نوبت هم‌پوشان |
| مراجعان | ثبت، جست‌وجو و ویرایش مراجعان ساختگی |
| تنظیمات | ساعات کاری هر روز، مدت هر نوبت، تعطیلات و مرخصی |
| مالی | ثبت پرداخت دستی، ثبت معکوس، فهرست پرداخت‌ها، گزارش مالی (فقط پزشک)، بیمه‌ها و روش‌های پرداخت |
| سایت عمومی | معرفی مطب و خدمات، ساعات کاری، پرسش‌های پرتکرار، تماس، دکمه واتس‌اپ و لینک اینستاگرام |
| پرسش‌ها | چت‌بات پاسخ به پرسش‌های پرتکرار از پاسخ‌های تأییدشده، و صفحه پرسش‌های بی‌پاسخ |
| پیام‌رسان | ربات تلگرام (و در صورت امکان بله) برای پاسخ پرسش‌ها و یادآوری نوبت فردا |
| بازخورد | فرم نظرسنجی یک‌بارمصرف پس از نوبت و داشبورد بازخورد |
| کاربران | ورود، دو نقش پزشک و منشی، مدیریت کاربران، کنترل دسترسی با RLS |

## خارج از محدوده — در این نسخه ساخته نمی‌شود

- پرونده پزشکی، اطلاعات بالینی، نسخه‌نویسی و تشخیص
- درگاه پرداخت آنلاین
- اپلیکیشن موبایل
- معماری میکروسرویس
- استفاده از مدل هوش مصنوعی یا ایجنت در خود محصول — چت‌بات و ربات فقط پاسخ‌های تأییدشده را برمی‌گردانند
- اتصال رسمی به API واتس‌اپ و اینستاگرام (دلیلش در `docs/channels-feasibility.md` مستند می‌شود)
- استفاده واقعی در مطب با داده واقعی مراجعان

## داده

**همه داده‌ها ساختگی‌اند.** هیچ نام، شماره تلفن، کد ملی، اطلاعات مالی یا پرونده واقعی هیچ‌کس وارد این پروژه نمی‌شود — حتی برای یک آزمون سریع.

## پیش از استفاده واقعی

نسخه فعلی **آموزشی** است. پیش از هر استفاده واقعی در مطب، این موارد باید جداگانه بررسی و تصمیم‌گیری شوند: میزبانی عملیاتی، پشتیبان‌گیری و بازیابی، امنیت و محرمانگی، الزامات قانونی، و مسئولیت‌های عملیاتی. چک‌لیست آن در کار `p1-17` نوشته می‌شود.
