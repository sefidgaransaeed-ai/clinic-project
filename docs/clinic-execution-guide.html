قواعد طلایی

  • هیچ‌کس مستقیم روی main کار نمی‌کند؛ هر تغییر از مسیر PR و بازبینی یک نفر دیگر.
  • هر نفر فقط در پوشه‌های خودش تغییر می‌دهد؛ فایل‌های مشترک (چیدمان، منو، package.json، supabase/) فقط دست نفر اول است.
  • تغییر پایگاه داده (جدول، ستون، تابع، قاعده دسترسی) را نفر دوم و سوم به‌صورت فایل migration در یک PR جداگانه پیشنهاد می‌دهند و فقط نفر اول آن را روی Supabase اعمال می‌کند.
  • فقط داده ساختگی؛ هیچ اطلاعات واقعی از مراجعان.
  • کلیدها فقط در .env.local و تنظیمات Vercel؛ هرگز در GitHub.
  • PR کوچک: کاری که بیش از یک روز طول می‌کشد، به چند PR کوچک‌تر شکسته شود.
  • قبل از هر PR: npm run build بدون خطا. و npm test از کار p1-09 به بعد — پیش از آن این دستور هنوز وجود ندارد، چون vitest در همان کار اضافه می‌شود.
  • در پروژه از مدل هوش مصنوعی یا ایجنت استفاده نمی‌شود؛ چت‌بات و ربات فقط پاسخ‌های تأییدشده را می‌دهند.

اگر وقت کم آمد: ترتیب کوچک‌کردن کار

تصمیم کاهش دامنه را نفر اول در جلسه ۹ آبان (و در صورت نیاز ۱۲ آبان) می‌گیرد.

هرگز حذف نمی‌شود

ورود و نقش‌ها و RLS، درخواست نوبت و تأیید منشی، نوبت‌ها و مراجعان، ثبت پرداخت و گزارش مالی، تنظیمات ساعات کاری و تعطیلات، مدیریت کاربران، سه آزمون خودکار، سایت عمومی و FAQ.

اول کوچک می‌شود

ربات «بله» (فقط تلگرام بماند)، نمودارهای داشبورد بازخورد (فقط عدد و فهرست)، ظاهر ویجت چت‌بات (فقط صفحه پرسش و پاسخ).

دوم کوچک می‌شود

یادآوری خودکار ربات (به‌جایش منشی فهرست نوبت‌های فردا را در پنل می‌بیند)، صفحه پرسش‌های بی‌پاسخ چت‌بات.

آخرین گزینه

ربات تلگرام به‌طور کامل به نسخه بعد منتقل می‌شود و گزارش آن به‌جایش ارائه می‌شود.

درباره واتس‌اپ و اینستاگرام: تیم «تلاش برای اجرا» را انتخاب کرد، اما طبق مستندات خود Meta، کسب‌وکارهای مستقر در ایران مجاز به استفاده از API رسمی واتس‌اپ نیستند و کاربران در ایران پیام‌های آن را دریافت نمی‌کنند؛ شرایط تجاری Meta هم فعالیت تجاری از کشورهای تحت تحریم آمریکا را محدود می‌کند. به همین دلیل در این برنامه به‌جای API، دکمه گفتگوی واتس‌اپ و لینک اینستاگرام در سایت به‌علاوه یک گزارش امکان‌سنجی مستند ساخته می‌شود، و ربات تلگرام (و در صورت امکان پیام‌رسان بله) نقش کانال پیام‌رسان را دارد.

آماده‌سازی رایانه (یک‌بار، برای هر سه نفر)

همه اعضا ویندوز دارند. مراحل را به ترتیب انجام دهید؛ هر مرحله حدود ۱۰ تا ۱۵ دقیقه طول می‌کشد. اگر در مرحله‌ای بیش از ۲۰ دقیقه گیر کردید، متن خطا را برای نفر اول بفرستید.

۱

PowerShell را باز کنید

دکمه Start ویندوز را بزنید، عبارت PowerShell را تایپ کنید و «Windows PowerShell» را باز کنید. پنجره‌ای آبی یا مشکی باز می‌شود که ابتدای خط آن PS C:\Users\YourName> است. همه دستورهای این راهنما در همین پنجره اجرا می‌شوند: دستور را کپی کنید، در پنجره راست‌کلیک کنید تا چسبانده شود و Enter بزنید.

بعد از نصب هر برنامه، پنجره PowerShell را ببندید و دوباره باز کنید تا ویندوز برنامه تازه را بشناسد. بیشتر خطاهای «پیدا نشد» با همین کار رفع می‌شوند.

۲

Git را نصب کنید

Git ابزاری است که تاریخچه تغییرات کد را نگه می‌دارد و Claude Code هم برای اجرای دستورها از Git Bash آن استفاده می‌کند.

دستور
winget install --id Git.Git -e --source winget

پنجره را ببندید و دوباره باز کنید، سپس با دستورهای زیر نصب را بررسی و نام و ایمیل خود را ثبت کنید. ایمیل همان ایمیل حساب GitHub شما باشد.

دستور
git --version
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

اگر کار نکرد: اگر دستور winget شناخته نشد، Git را از git-scm.com دانلود و با گزینه‌های پیش‌فرض نصب کنید.

۳

Node.js (نسخه LTS) را نصب کنید

Node.js موتور اجرای پروژه Next.js روی رایانه شماست.

دستور
winget install OpenJS.NodeJS.LTS

پنجره را دوباره باز کنید و بررسی کنید. هر دو دستور باید یک شماره نسخه نشان دهند.

دستور
node -v
npm -v

اگر کار نکرد: اگر winget کار نکرد، نسخه LTS را از nodejs.org دانلود کنید. اگر PowerShell هنگام اجرای npm خطای «running scripts is disabled» داد، یک‌بار این دستور را بزنید: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

۴

VS Code و GitHub CLI را نصب کنید

VS Code برای دیدن و خواندن فایل‌هاست و GitHub CLI (دستور gh) برای ساختن و گرفتن مخزن و Pull Request از داخل PowerShell.

دستور
winget install Microsoft.VisualStudioCode
winget install --id GitHub.cli

پنجره را دوباره باز کنید و به GitHub وصل شوید. گزینه‌ها را این‌طور انتخاب کنید: GitHub.com، HTTPS، Yes برای استفاده در Git، و Login with a web browser. کد هشت‌حرفی را در مرورگر وارد کنید.

دستور
gh auth login
gh auth status
۵

Claude Code را نصب کنید و وارد شوید

این دستور رسمی نصب روی ویندوز است. هنگام دانلود پیشرفتی نشان نمی‌دهد؛ صبر کنید تا تمام شود.

دستور
irm https://claude.ai/install.ps1 | iex

پنجره را ببندید و دوباره باز کنید. سپس نسخه را بررسی کنید و یک‌بار claude را اجرا کنید تا مرورگر برای ورود با حساب Claude باز شود. اگر مشکلی بود، claude doctor وضعیت نصب را گزارش می‌دهد.

دستور
claude --version
claude doctor
claude

اگر کار نکرد: Claude Code به اشتراک Pro یا بالاتر نیاز دارد. اگر بعد از نصب پیام «claude is not recognized» آمد، پنجره را دوباره باز کنید؛ اگر باز هم ماند، رایانه را یک‌بار ری‌استارت کنید.

۶

پوشه کار بسازید

همه اعضا پروژه را در یک مسیر یکسان نگه می‌دارند تا راهنماها برای همه یکی باشد.

دستور
mkdir $HOME\Projects
cd $HOME\Projects

نفر اول در این پوشه پروژه را می‌سازد. نفر دوم و سوم بعد از دریافت دعوت‌نامه GitHub، پروژه را با دستور زیر در همین پوشه می‌گیرند:

دستور
gh repo clone sefidgaransaeed-ai/clinic-project
cd clinic-project
npm install

معیار پایان آماده‌سازی

  • git --version، node -v، gh auth status و claude --version همه بدون خطا جواب می‌دهند.
  • با اجرای claude در پوشه پروژه، Claude Code باز می‌شود و به پیام «سلام» جواب می‌دهد.
  • پوشه Projects\clinic-project روی رایانه شما وجود دارد (برای نفر دوم و سوم پس از ۲۸ مهر).

کلیدها و فایل .env.local

برنامه برای اتصال به Supabase و ربات به چند مقدار محرمانه نیاز دارد. این مقادیر در فایلی به نام .env.local در ریشه پروژه نگه داشته می‌شوند که هرگز وارد GitHub نمی‌شود. نفر اول مقادیر را از ۵ آبان در پیام خصوصی می‌فرستد؛ شما فایل .env.example را کپی و با نام .env.local ذخیره و پر می‌کنید.

پیش از PR بررسی کنید

این دو دستور باید بدون خطا تمام شوند. اگر خطا داد، متن خطا را به Claude بدهید و بخواهید علتش را به زبان ساده توضیح دهد و رفعش کند.

۶

ثبت تغییرات و ساخت PR

می‌توانید از Claude بخواهید: «تغییرات را با یک پیام روشن commit کن، شاخه را push کن و با gh یک Pull Request با توضیح فارسی بساز.» یا خودتان این دستورها را بزنید:

دستور
git add .
git commit -m "short description of the change"
git push -u origin HEAD
gh pr create --fill
۷

بازبینی و ادغام

وضعیت کار را در پنل پروژه به‌روز کنید و لینک PR را در یادداشت همان کار بگذارید. لینک PR را در گروه هم بفرستید. بازبین در صفحه PR روی تب «Files changed» تغییرات را می‌بیند و لینک پیش‌نمایش Vercel را که خودکار زیر PR می‌آید باز می‌کند. اگر درست بود «Approve» و سپس «Squash and merge» می‌زند. بعد از ادغام، صاحب شاخه به main برمی‌گردد.

دستور
git checkout main
git pull

چطور با Claude Code کار کنیم

یک کار در هر گفتگو

بین دو کار متفاوت دستور /clear را بزنید تا گفتگوی قبلی ذهن Claude را شلوغ نکند. گفتگوی طولانی هم سهمیه استفاده اشتراک را سریع‌تر مصرف می‌کند.

همیشه به منبع اشاره کنید

پرامپت‌ها با «طبق CLAUDE.md و docs/data-model.md» شروع می‌شوند تا Claude از تصمیم‌های تیم بیرون نرود.

اول برنامه، بعد کد

برای کار بیش از چند فایل، در Plan mode بخواهید برنامه بدهد. اگر برنامه به پوشه دیگران یا فایل مشترک دست می‌زند، رد کنید و بگویید فقط در پوشه خودت.

توضیح بخواهید

بعد از هر کار بپرسید: «به زبان ساده و فارسی بگو چه فایل‌هایی را تغییر دادی، چه دستوری اجرا کردی و چه چیزی هنوز حل نشده است.» این همان قاعده CLAUDE.md است.

خطا را کامل بدهید

وقتی خطایی دیدید، کل متن خطا را کپی کنید و بنویسید: «این خطا را دیدم وقتی X را انجام دادم. علتش را توضیح بده و رفعش کن.»

هرگز کلید ندهید
