## این فایل چیست و چه چیزی نیست

این فایل **مرجع هیچ چیزی نیست.** فقط می‌گوید «چه چیزی تازه عوض شده» و «هر چیزی را کجا پیدا کنید».

> ⛔ **در جدول ترتیب اعتبار اسناد (`CLAUDE.md` بخش ۰) جایی ندارد و نباید داشته باشد.** اگر این فایل با سند دیگری اختلاف داشت، **آن سند درست است، نه این.** هیچ تصمیمی را از اینجا نقل نکنید؛ از منبعش نقل کنید.

دلیل وجودش یک چیز است: اسناد پروژه بزرگ‌اند و کسی ۱۸۶ کیلوبایت راهنما را دوباره نمی‌خواند تا بفهمد سه خطش عوض شده.

## 🔴 قاعده طلایی — پیش از شروع هر کار

```bash
git checkout main
git pull origin main
```

**پرامپت‌های راهنمای اجرایی عوض شده‌اند.** اگر از نسخه قدیمی شاخه خودتان بخوانید، پرامپتی را اجرا می‌کنید که با مدل داده نمی‌خواند و کدش کار نخواهد کرد.

این واقعاً اتفاق افتاد: پرامپت کار `p2-08` فیلد **کد ملی** را جا انداخته بود، در حالی که تابع پایگاه داده بدون آن ثبت نمی‌کند.

## چه چیزی برای شما عوض شد

بازبینی مدل داده ۲۲ تصمیم تازه تولید کرد. این‌ها روی کارهای شما اثر **مستقیم** دارند:

### خانم مریم — چهار کار

| کار | چه عوض شد |
|---|---|
| `p2-03` فرم مراجع | دو فیلد تازه: **تاریخ تولد شمسی** و **جنس** (هر دو اختیاری). موبایل هم **اختیاری** شد |
| `p2-04` پنجره تأیید درخواست | تطبیق مراجع **فقط با کد ملی** — نه با موبایل |
| `p2-08` فرم `/nobat` | **کد ملی** (که در پرامپت جا افتاده بود) + انتخاب «برای خودم / برای شخص دیگری» + امضای تازه تابع |
| ربات تلگرام | تطبیق دو مرحله‌ای: اول `patients.mobile`، اگر نبود `appointments.requester_mobile` |

### خانم هستی — سه کار

| کار | چه عوض شد |
|---|---|
| `p3-04` فهرست پرداخت‌ها | منشی **فقط پرداخت‌های امروز** را می‌بیند. فیلتر بازه تاریخ برای نقش منشی گذاشته نمی‌شود |
| `p3-13` تنظیمات سایت | فرم پرسش‌ها یک فیلد **کلیدواژه** می‌گیرد؛ فرم اطلاعات سایت **۱۱ کلید** دارد، نه چهار |
| `p3-09` لینک نظرسنجی | فهرست را از تابع `done_appointments_without_survey(days)` بخوانید، نه از جدول `surveys` |

### هر دو

| کار | چه عوض شد |
|---|---|
| `p3-08` آزمون مالی | مورد آزمون مرز روز به **ساعت بامدادی** عوض شد. ساعت ۲۳:۵۰ اشکال را نمی‌گرفت |

**متن کامل پرامپت‌ها در راهنمای اجرایی به‌روز شده است.** لازم نیست چیزی را حدس بزنید — فقط `git pull` بزنید و پرامپت کار خودتان را بخوانید.

## اگر تعارضی دیدید

**خودتان حلش نکنید.** سند بالاتر در جدول ترتیب اعتبار (`CLAUDE.md` بخش ۰) را اجرا کنید و تعارض را گزارش دهید تا در `docs/decisions/` ثبت شود.

این روال دو بار در همین پروژه کار کرد و هر دو بار یک اشکال واقعی را گرفت. گزارش دادن تعارض، کار درست است — نه مزاحمت.

**و اگر ایرادی گرفتید که جوابی برایش نیامد، پسش نگیرید.** ایراد را تا گرفتن جواب فنی نگه دارید. تصمیم قبلی بودنِ چیزی، جواب نیست.
