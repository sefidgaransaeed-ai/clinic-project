# 0002 — فایل تمرین PR برای هر عضو جدا باشد

- **تاریخ:** ۲۸ مهر ۱۴۰۵
- **وضعیت:** تأییدشده

## زمینه

راهنمای اجرایی در کارهای `p2-02` (مریم) و `p3-02` (هستی) از هر دو عضو می‌خواهد فایل `docs/team.md` را تغییر دهند و «اگر نیست، بسازند». این دو مشکل داشت:

**۱. تعارض با قاعده مالکیت.** بخش ۳ فایل `CLAUDE.md` پوشه `docs/` را کامل به نفر اول می‌دهد. یعنی راهنمای اجرایی چیزی می‌خواست که `CLAUDE.md` منع کرده بود.

**۲. تعارض merge واقعی — نه فرضی.** بررسی نشان داد:

| شاهد | مقدار |
|---|---|
| تاریخ `p2-02` | ۲۸ مهر |
| تاریخ `p3-02` | ۲۸ مهر — همان روز |
| متن هر دو پرامپت | «فقط فایل `docs/team.md` را تغییر بده (اگر نیست، بساز)» |
| آیا فایل وجود دارد؟ | نه — در هیچ شاخه‌ای |

هر دو نفر در یک روز یک فایل ناموجود را از صفر می‌ساختند. نتیجه‌اش یک merge conflict از نوع `add/add` بود برای هر کس که دوم PR می‌داد — نوعی که git نمی‌تواند خودکار حلش کند.

## تصمیم

به‌جای یک فایل مشترک، **هر عضو فایل خودش را دارد**:

```
docs/team/maryam.md
docs/team/hasti.md
```

قاعده مالکیت در `CLAUDE.md` این جمله را می‌گیرد: **هر کس فقط فایل خودش در `docs/team/`**.

## دلیل

- **اولین PR عمر یک مبتدی نباید با merge conflict شروع شود.** این دلیل اصلی است، نه تعارض مالکیت.
- قاعده مالکیت یک جمله روشن می‌شود به‌جای تبصره مبهم روی یک فایل خاص.
- تمرین هیچ چیزی از دست نمی‌دهد: شاخه، commit، push، PR و بازبینی همه سر جایشان‌اند.

## گزینه‌های بررسی‌شده و رد‌شده

| گزینه | چرا رد شد |
|---|---|
| `docs/team.md` را استثنای قاعده کنیم | تبصره مبهم می‌سازد و مشکل اصلی یعنی تعارض merge را اصلاً حل نمی‌کند |
| سخت نگیریم، تمرین است | اولین درس تیم این می‌شد که قاعده‌های `CLAUDE.md` تزئینی‌اند. بعداً که قاعده‌ای واقعاً مهم شد — مثل RLS یا کلید سرویس — دیگر جدی گرفته نمی‌شد |

## پیامد

| کجا | چه تغییری |
|---|---|
| `CLAUDE.md` بخش ۳ | یک خط: صاحب `docs/team/<name>.md` خود همان عضو است |
| `docs/clinic-execution-guide.html` | ۳ ارجاع به `docs/team.md` اصلاح شود (پرامپت `p2-02`، پرامپت `p3-02`، و شرح کار نفر اول) |

**زمان اجرا:** در یک PR سوم، **بعد از** ادغام PR #1 و #2. دلیل: اگر همین حالا commit زده شود، دیفی که مریم در حال بازبینی است زیر دستش عوض می‌شود و برای کسی که اولین بار بازبینی می‌کند گیج‌کننده است. عجله‌ای هم نیست — این تغییر فقط پیش از شروع `p2-02` و `p3-02` لازم است، که خودشان بعد از ادغام PR #2 شروع می‌شوند (چون پرامپتشان به `CLAUDE.md` ارجاع می‌دهد و آن فایل هنوز روی `main` نیست).
