## تصمیم

### ۱. ترتیب اعتبار اسناد

بخش تازه‌ای با همین عنوان به **ابتدای `CLAUDE.md`** اضافه شد:

| ترتیب | سند |
|---|---|
| ۱ | `CLAUDE.md` |
| ۲ | `docs/project-scope.md` |
| ۳ | `docs/data-model.md` |
| ۴ | `docs/clinic-project-plan-v0.5.html` |
| ۵ | `docs/brand-voice.md` |
| ۶ | `docs/clinic-execution-guide.html` |

**اگر دو سند تعارض داشتند، سند بالاتر معتبر است.**

**چرا این ترتیب:** هرچه بالاتر، تغییرش گران‌تر و اثرش گسترده‌تر. `CLAUDE.md` قواعد کار و مالکیت را تعیین می‌کند؛ راهنمای اجرایی فقط می‌گوید فردا چه کار کنیم.

**قاعدهٔ همراهش:** کسی که تعارض را می‌بیند **حق حل‌کردنش را ندارد**. باید سند بالاتر را اجرا کند و تعارض را در `docs/decisions/` ثبت کند. دلیلش این است که تعارض‌ها معمولاً نشانهٔ یک تصمیم نگرفته‌اند، نه یک غلط تایپی.

### ۲. قاعدهٔ `npm test` صادق شد

متن راهنمای اجرایی از «پیش از هر PR، `npm run build` و `npm test` بدون خطا» به این تغییر کرد: `npm run build` همیشه، و **`npm test` از کار `p1-09` به بعد** — چون vitest در همان کار اضافه می‌شود.

**چرا مهم بود:** عضو تازه‌ای که `npm test` را می‌زد، با خطا روبه‌رو می‌شد و فکر می‌کرد کاری را اشتباه کرده. `CLAUDE.md` از قبل صادق بود؛ راهنمای اجرایی نبود.

### ۳. فهرست تصمیم‌ها کامل شد

`0002` و `0003` و `0004` و `0005` به جدول `docs/decisions/README.md` اضافه شدند.
