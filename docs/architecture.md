# نمای کلی معماری

## اجزا

| جزء | نقش |
|---|---|
| رایانه هر عضو + Claude Code | نوشتن، اصلاح و آزمون کد |
| مخزن GitHub | شاخه‌ها، Pull Request و بازبینی تغییرات |
| Vercel | انتشار برنامه Next.js و ساخت پیش‌نمایش برای هر PR |
| Supabase | پایگاه داده PostgreSQL، احراز هویت، و کنترل دسترسی با RLS |

**یک برنامه واحد و ماژولار — بدون میکروسرویس.** هر حوزه کاری یک پوشه زیر `src/modules/` است با یک صاحب مشخص.

## جریان کار

```
کاربر ناشناس (سایت)                کاربر وارد‌شده (پنل)
        │                                   │
        ▼                                   ▼
   src/app/(site)                     src/app/panel
        │                                   │
        │ فقط از طریق تابع (RPC)            │ با نقش pزشک یا منشی
        ▼                                   ▼
            Supabase — RLS روی همه جدول‌ها
```

- **کاربر ناشناس** به هیچ جدولی دسترسی مستقیم ندارد. فقط چند تابع مشخص (`available_slots`، `request_appointment`، `get_public_info`، `get_survey`، `submit_survey`) برایش باز است.
- **کاربر وارد‌شده** نقشش در `app_metadata` حساب Supabase ذخیره می‌شود و RLS از همان‌جا می‌خواند — نه از جدولی که خودش بتواند عوض کند.
- **کنترل دسترسی در پایگاه داده است، نه در رابط کاربری.** پنهان‌کردن یک دکمه کافی نیست.

## لایه‌های کد

| لایه | مسیر | قاعده |
|---|---|---|
| مسیرها و صفحه‌ها | `src/app/` | چیدمان و منوی پنل فقط دست نفر اول |
| ماژول‌های کاری | `src/modules/<name>/` | هر ماژول یک صاحب؛ ارتباط بین ماژول‌ها یک‌طرفه |
| خواندن و نوشتن داده | `src/modules/<name>/data.ts` | جدا از رابط کاربری، تا تعویض منبع داده فقط یک فایل را عوض کند |
| کد مشترک | `src/lib/` | اتصال Supabase، قالب‌بندی تاریخ و مبلغ، بررسی نقش — فقط نفر اول |
| ساختار پایگاه داده | `supabase/migrations/` | فقط نفر اول اعمال می‌کند؛ بقیه با PR پیشنهاد می‌دهند |

## کلیدها

| کلید | کجا استفاده می‌شود |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY` | هم سرور، هم مرورگر — با RLS محافظت می‌شوند |
| `SUPABASE_SERVICE_ROLE_KEY` | **فقط سمت سرور**، در فایلی با `import 'server-only'` |

## محل استقرار

دسترسی اعضا به GitHub، Vercel و Supabase از ایران بررسی شده و مشکلی گزارش نشده است. **این تأیید برای محیط آموزشی است**؛ میزبانی استفاده واقعی جداگانه تعیین می‌شود.

## آنچه هنوز طراحی نشده

جزئیات کامل امنیت، پشتیبان‌گیری، بازیابی و تنظیمات انتشار پیش از استفاده واقعی طراحی می‌شوند. ساختار دقیق داده در `docs/data-model.md` می‌آید و تا تأیید آن، هیچ جدول یا صفحه متصل به پایگاه داده ساخته نمی‌شود.
